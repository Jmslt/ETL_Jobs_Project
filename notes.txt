15/10

On Airflow:
- The easiest was to add the sql server to the docker compose
- I wanted ot use Airflow's connector directly instead of relying on SQLalchemy
- Best way to do this was to add a MSSQL connection string to Airflow, and to install the MSSQL connector package inside
  Airflow (using the PIP env variable in the docker compose)
- Last problem was to use the correct server name in the connection string: localhost is usable by the client on the
  host machine, but to connect 2 different services in the same docker compose I needed to use the service name (sql_tfe)

- The keyword GO in TSQL is not useable correctly with Airflow's connector. The GO keyword is a clientside function, not
  sql server side. This means I have to be careful with the order of my SQL statements.

- It is easier to create different connections to the Silver and Gold DB in order to use the right schemas; it is too
  difficult to use SQL code like 'USE DB' because we cannot use GO.
- For views, I needed to set the SQL execution 'split_statements' to True. Apparently it takes a SQL string (here,
  a file) and divides it into statements, replacing the need for GO. I did not try without ';' a the end of CREATE
statements, but it works with them.
